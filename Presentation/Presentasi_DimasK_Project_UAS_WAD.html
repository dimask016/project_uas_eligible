Alur Kerja MVC (Request Life Cycle)

Siklus permintaan (request life cycle) dari pengguna hingga data berhasil disimpan di basis data menggunakan arsitektur MVC dengan kombinasi Inertia.js:

[Browser / React View] ---> (HTTPS Request) ---> [Laravel Router] | [Database / Eloquent Model] <--- (Logic & DB) <--- [Controller]

Tahap 1: Interaksi di View (Frontend React)

  • User Action: Pengguna menekan tombol "BAYAR SEKARANG" di halaman checkout (resources/js/Pages/Web/Checkouts/Index.jsx).
  • State & Event Handler: Elemen form memicu fungsi storeCheckout(). Fungsi ini mengumpulkan data state alamat, ongkir, serta payment_method.
  • Inertia Request: Inertia mengirimkan HTTP POST request berisi payload JSON ke rute /checkouts backend tanpa memuat ulang (reload) seluruh halaman.

Tahap 2: Routing & Control (Laravel Controller)

  • Routing: routes/web.php mengarahkan HTTP POST /checkouts ke method store() di CheckoutController.php.
  • Validation & Security: Controller memvalidasi parameter (province_id, city_id, dll) dan menghitung ulang harga dari database untuk mencegah manipulasi (price tampering).

Alur Kerja MVC (Lanjutan)

Tahap 2 (Lanjutan): Integrasi Payment Gateway

  • Controller membuat Signature MD5 Duitku, menyusun payload transaksi, dan mengirim request via HTTP Client ke API Endpoint Duitku Sandbox.

Tahap 3: Interaksi dengan Model & Database

  • Database Transaction: Jika API Duitku merespons sukses (statusCode == '00'), Controller membuka transaksi basis data (DB::transaction).
  • Model Invoice menyimpan data transaksi baru (status UNPAID, detail pengiriman, dan paymentUrl dari Duitku).
  • Model Cart menghapus (delete) item keranjang belanja milik user tersebut.

Tahap 4: Respons Kembali ke View

  • Inertia Location Redirect: Controller mengembalikan respons Inertia::location($result['paymentUrl']).
  • Browser Navigation: Browser secara otomatis mengalihkan halaman pengguna dari 2R STORE menuju halaman transaksi Sandbox Duitku.

Alur Diagram Customer (Customer Journey)

  1. Pemilihan Produk: Customer memilih produk, variasi Warna, Ukuran, dan Jumlah (Qty).
  2. Autentikasi Pengguna (Guest Guard): Saat klik "Add to Cart", sistem mengecek login. Jika belum, diarahkan ke Login / Register. Setelah sukses, kembali ke Home.
  3. Manajemen Keranjang Belanja: Customer dapat mengubah jumlah pesanan atau menghapus produk di halaman keranjang.
  4. Proses Pengiriman (RajaOngkir): Di halaman Checkout, customer memilih Provinsi → Kota → Kecamatan. Sistem memanggil API RajaOngkir untuk tarif ongkir real-time (JNE, POS, J&T, Ninja).
  5. Pembayaran Gateway (Sandbox Duitku): Customer mengisi alamat, menekan "BAYAR SEKARANG". Sistem membuat invoice dan mengarahkan ke gateway Sandbox Duitku (Virtual Account/Credit Card).

Desain Basis Data (ERD & Relasi Tabel)

Relasi One-to-Many (1:N): Categories & Products

Alasan: Sebuah produk (misal: Jaket Parka) hanya dikategorikan ke dalam 1 kategori spesifik. Namun, 1 kategori dapat menampung banyak produk berbeda.

Implementasi Migration (Foreign Key)

Schema::create('products', function (Blueprint $table) { $table->id(); $table->foreignId('category_id')->constrained('categories')->onDelete('cascade'); $table->string('title'); $table->bigInteger('price'); $table->timestamps(); });

Pemanggilan Data Relasional (Eloquent ORM)

// Model Product public function category() { return $this->belongsTo(Category::class); } // Eager Loading (Mencegah N+1 Problem) $products = Product::with(['category', 'colors'])->latest()->paginate(10);

Keamanan Web (Pencegahan XSS)

Cross-Site Scripting (XSS)

Serangan menyisipkan skrip berbahaya via input form yang dieksekusi di browser pengguna lain.

  • Frontend (React Auto-Escaping): React secara default memperlakukan nilai variabel di dalam kurung kurawal JSX { variable } sebagai plain text. String seperti <script>alert('XSS')</script> otomatis di-escape menjadi entitas HTML aman.
  • Backend (Sanitasi Input): Server memvalidasi data input melalui $request->validate([...]) sebelum diproses.
  • Cookies & Session Protection: Status autentikasi disimpan dalam cookie HTTP-Only dan SameSite. Skrip jahat tidak dapat membaca token sesi via document.cookie.
// config/session.php 'http_only' => env('SESSION_HTTP_ONLY', true), 'same_site' => env('SESSION_SAME_SITE', 'lax'), 'secure' => env('SESSION_SECURE_COOKIE'),

Keamanan Web (Pencegahan SQL Injection)

SQL Injection terjadi ketika penyerang memasukkan kueri SQL berbahaya ke dalam kolom input untuk memanipulasi database.

Solusi: Eloquent ORM & PDO Parameter Binding

Nilai input dikirim terpisah dari struktur perintah SQL. Karakter khusus SQL seperti ' OR '1'='1 dianggap sebagai string biasa.

// Input dimasukkan melalui PDO Prepared Statement Product::create([ 'category_id' => $request->category_id, 'title' => $request->title, 'price' => $request->price, ]);

Logika Autentikasi & Session

  1. Pengiriman Request: Input email & password dari React dikirim via POST ke /login.
  2. Validasi Request: Input divalidasi dengan $request->validate().
  3. Pemeriksaan Kredensial (Bcrypt): Menggunakan Auth::attempt(). Password dicocokkan dengan hash di database menggunakan Bcrypt (Hash::check()).

Penyimpanan Session Secara Aman

  • Server-side Session: Tidak menggunakan JWT di local storage (rentan XSS).
  • HTTP-Only Cookies: Mencegah JavaScript mengakses cookie sesi.
  • Regenerasi Session ID: $request->session()->regenerate() setiap login untuk mencegah Session Fixation.

Proteksi Hak Akses (Middleware)

Halaman sensitif dilindungi middleware auth. Jika unauthorized, server redirect ke /login. Status user dibagikan ke React via HandleInertiaRequests.

Deployment AWS EC2 (Infrastruktur & Load Balancing)

1. Provisioning & Security Group

Membuat instans EC2 (Amazon Linux 2023). Mengonfigurasi Security Group (Firewall):

  • Port 22 (SSH): Terbatas IP Pengembang.
  • Port 8000 (HTTP) & 443 (HTTPS): Terbuka (0.0.0.0/0).
  • Port 5177 (Vite) & 3306 (MySQL): Untuk layanan tambahan.

2. Create AMI Image

Membuat Amazon Machine Image untuk *backup* dan replikasi *instance*:

Nama: ami-app-web-v1
AMI ID: ami-02ed7bbd831e5a74d

3. Create Target Group

Membuat Target Group untuk mendistribusikan trafik dari Load Balancer ke Instance:

Nama: tg-app-web
Port: 8000 (HTTP)
Target Type: Instance
Load Balancer: alb-app-web

4. Create Load Balancing

Membuat Application Load Balancer (ALB) untuk *high availability*:

Nama: alb-app-web
Scheme: Internet-facing
IP Type: IPv4
Availability Zones: 2 (High Availability)

5. Cloning Repository & Build

  • Link Repository: https://github.com/dimask016/project_uas_eligible
  • Build & Instalasi: composer install --no-dev dan npm install && npm run build.

6. Buat service systemd

Buka file service:

sudo nano /etc/systemd/system/laravel.service

Masukkan konfigurasi berikut:

[Unit] Description=Laravel Artisan Development Server After=network.target [Service] User=ec2-user WorkingDirectory=/home/ec2-user/docker_web ExecStart=/usr/bin/php artisan serve --host=0.0.0.0 --port=8000 Restart=always

Aktifkan dan cek status service:

sudo systemctl daemon-reload sudo systemctl enable --now laravel sudo systemctl status laravel

7. Akses Web & Database

  • Akses Web: ec2-32-236-168-110.ap-southeast-2.compute.amazonaws.com:8000
  • Load Balancing App: alb-app-web-1871278509.ap-southeast-2.elb.amazonaws.com
  • Database: ec2-13-210-247-47.ap-southeast-2.compute.amazonaws.com
